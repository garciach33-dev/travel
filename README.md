# 旅行規劃與紀錄工具

一個純前端的旅行工具：行前準備、行李分人打包、藥品管理、每日行程與 Google Maps 導航、天氣預報、支出記帳、遊記與影音紀錄。

預設**不需要伺服器、不需要帳號**，資料存在使用者自己的瀏覽器。另可選用 Supabase 開啟**雲端同步**：一組空間名稱 + 一組密碼，所有旅程跨裝置、多人共用，內容端對端加密。

---

## 檔案清單

| 檔案 | 用途 |
|---|---|
| `index.html` | 工具本體（單檔，包含所有 CSS 與 JS） |
| `manifest.webmanifest` | 讓手機可以「加入主畫面」變成 App |
| `sw.js` | 離線快取，第二次之後沒網路也能開 |
| `icon.svg` / `icon-192.png` / `icon-512.png` / `icon-512-maskable.png` | 圖示 |
| `.nojekyll` | 讓 GitHub Pages 不要用 Jekyll 處理檔案（必要，別刪） |
| `supabase-setup.sql` | 雲端同步用的資料庫設定（選用，見下方） |
| `README.md` | 這份說明（不影響網站運作） |

**這些檔案要放在同一層目錄**，不要分資料夾。

## 發佈到 GitHub Pages

### 第一次上架

1. 到 <https://github.com> 註冊 / 登入。
2. 右上角 **+ → New repository**。
   - **Repository name** 填一個好記的英文名，例如 `travel-kit`
   - 選 **Public**
   - 其他不用勾，按 **Create repository**
3. 進入剛建立的 repository，點 **Add file → Upload files**。
4. 把上面清單的檔案**全部**拖進去。
   - `.nojekyll` 是隱藏檔。Mac 在 Finder 按 `Cmd + Shift + .` 可以顯示隱藏檔；Windows 在檔案總管勾選「隱藏的項目」。
   - 如果真的拖不進去，可以改用網頁上的 **Add file → Create new file**，檔名輸入 `.nojekyll`，內容留空，按 Commit。
5. 下方按 **Commit changes**。
6. 上方 **Settings → Pages**（左側選單）。
   - **Source** 選 `Deploy from a branch`
   - **Branch** 選 `main`、資料夾選 `/ (root)`，按 **Save**
7. 等 1～3 分鐘，重新整理該頁，最上方會出現網址：

   ```
   https://你的帳號.github.io/travel-kit/
   ```

   這就是可以分享給大家的網址。

### 之後要更新

改好新的 `index.html` 之後：

1. 進入 repository，點進 `index.html`
2. 右上角鉛筆圖示 **Edit**（或直接 **Add file → Upload files** 覆蓋上傳）
3. 貼上新內容 → **Commit changes**
4. 約 1 分鐘後生效

> **重要**：因為有離線快取，更新後請把 `sw.js` 裡的
> `const VERSION = 'v1';` 改成 `'v2'`、`'v3'`…
> 使用者下次連上網才會拿到新版。不改的話他們可能一直看到舊版。

## 給使用者的說明（可以直接貼給朋友）

- **網址打開就能用**，不用註冊、不用安裝。
- 資料存在自己的手機／電腦裡，**別人看不到，我們也看不到**。
- 換裝置或清除瀏覽資料就會不見 → 記得定期按右上角 **「匯出全部」** 下載備份檔。
- 要把行程傳給同行者：按 **「匯出這趟」**，把 `.json` 檔傳給對方，對方按 **「匯入」**。

  - **iPhone (Safari)**：分享鍵 → 加入主畫面
  - **Android (Chrome)**：右上角 ⋮ → 安裝應用程式 / 加到主畫面
- 加到主畫面後，**沒網路也能開**（天氣與地圖需要網路）。

## 需要注意的事

- **無痕／隱私模式**下瀏覽器可能不允許儲存，工具會在右上角顯示「無法自動儲存」，這時請務必用匯出備份。
- **Safari** 若使用者超過 7 天沒開這個網站，可能會清掉 localStorage（ITP 政策）。長期資料請以匯出檔為準。
- 天氣資料來自 [Open-Meteo](https://open-meteo.com/)（免費、免金鑰、非商業使用免授權）；匯率來自 [Frankfurter](https://frankfurter.app/)。兩者都直接由使用者的瀏覽器呼叫，不經過任何中介伺服器。
- 藥品與健康相關內容僅為一般性提醒，**不構成醫療建議**。

## 雲端同步（選用）— 一組密碼，跨裝置、多人共用

不設定的話，工具照樣能用，只是資料只留在各自的裝置上。
設定之後，會多出「共用空間」：**一組空間名稱 + 一組密碼**，底下裝你**所有旅程**。
任何裝置輸入這兩個，看到的就是全部旅程與所有編輯紀錄；之後新增旅程不用再設定，自動同步。

### 設定步驟（約 10 分鐘，免費）

**1. 建立 Supabase 專案**

1. 到 <https://supabase.com> → **Start your project** → 用 GitHub 帳號登入
2. **New project**
   - Name：隨便取，例如 `travel`
   - Database Password：系統會產生一組，**存起來**（這是資料庫密碼，跟共用空間密碼無關）
   - Region：選 **Northeast Asia (Tokyo)** 或 **Southeast Asia (Singapore)**，離台灣近
   - Plan 選 **Free**
3. 按 **Create new project**，等 1～2 分鐘建置完成

**2. 建立資料表與函式**

1. 左側選單 → **SQL Editor** → **New query**
2. 把 `supabase-setup.sql` 的內容**整份**貼進去
3. 按右下角 **Run**（或 Ctrl/Cmd + Enter）
4. 看到 `Success. No rows returned` 就成功了

**3. 取得金鑰**

1. 左側最下面 **Project Settings**（齒輪）→ **API**
2. 複製兩個值：
   - **Project URL**，長得像 `https://abcdefghijklm.supabase.co`
   - **API Keys → anon / public**（新版介面可能叫 **Publishable key**），一長串 `eyJ...`

**4. 貼進 index.html**

用文字編輯器打開 `index.html`，搜尋 `SUPA_URL`，把兩行改成你的值：

```js
const SUPA_URL = 'https://abcdefghijklm.supabase.co';
const SUPA_KEY = 'eyJhbGciOiJIUzI1NiIsInR5cCI6...';
```

存檔，重新上傳到 GitHub（記得把 `sw.js` 的 `VERSION` 加 1）。

> **這兩個值放在網頁原始碼裡是安全的。** anon key 本來就設計成公開的，
> 真正的保護在 `supabase-setup.sql`：資料表開了 RLS 但沒有任何 policy，
> 所以拿 anon key 也**無法直接讀寫資料表**，只能呼叫那幾個要驗密碼的函式。
> 而且內容本身是端對端加密的（見下方）。

**5. 測試**

打開網站 → 總覽最上方 → **建立共用空間** → 取名稱、設密碼 →
換一台裝置（或無痕視窗）開同一個網址 → **登入既有空間** → 輸入同一組 → 應該看到你所有旅程。

### 使用方式

| 動作 | 說明 |
|---|---|
| 建立共用空間 | 把這台目前的**所有旅程**上傳，取一個空間名稱與密碼 |
| 登入既有空間 | 在別的裝置輸入同一組，取得全部旅程 |
| 複製分享訊息 | 一次複製網址＋空間名稱＋密碼，直接貼給同行者 |
| 立即更新 | 手動抓雲端最新版 |
| 強制上傳 | 用這台的版本覆蓋雲端 |
| 變更密碼 | 用新密碼重新加密整份，換完要通知同行者 |
| 登出 | 這台不再同步，資料留在本機；隨時可再登入回來 |
| 從雲端刪除 | 整個空間永久刪除，所有裝置都讀不到 |

- 分享連結長這樣：`https://你的網址/?s=空間名稱` — 點開後會問密碼。
- **一組密碼走天下。** 不管幾趟旅程、換幾台裝置，都只用這一組。新增旅程不必再設定任何東西。
- 空間名稱規則：4～24 個英數字，自動轉大寫，全世界不能重複（撞名會請你換一組）。
- 登入時如果這台裝置本來就有旅程，會問你要**併入空間**還是**只用雲端的**，不會默默弄丟。

### 同時修改怎麼辦

每次儲存都會帶版本號。如果你和同行者同時改了，工具會跳出提示讓你選「採用雲端版本」或「用我這台覆蓋雲端」，不會靜靜地把資料吃掉。
另外，正在打字時不會被雲端的更新打斷，會等你停下來再套用。

### 端對端加密

內容在**你的瀏覽器裡**就加密好才送出，Supabase 上只有密文。

```
salt      = SHA-256("travelkit.v1|" + 空間名稱)
512 bits  = PBKDF2-SHA256(你的密碼, salt, 310,000 次)
            ├─ 前 256 bits → AES-256-GCM 金鑰，只留在瀏覽器
            └─ 後 256 bits → 驗證 token，送給伺服器做 bcrypt 比對
```

意思是：

- **真正的密碼從不離開瀏覽器。** 送出去的只有推導出來的驗證 token。
- **連你自己在 Supabase 後台也讀不到內容**，只會看到 `{"e":1,"iv":"...","ct":"..."}` 這樣的密文。
- 資料庫被偷、連線被側錄，拿到的都是密文。
- 兩把金鑰互相獨立，拿到驗證 token 推不出解密金鑰。

代價：

- **沒有「忘記密碼」。** 密碼是唯一的解密金鑰，弄丟就永久打不開，任何人都救不回來——包括你。請務必自己另存一份，並定期用「匯出全部」下載備份。
- 需要 **https** 才能運作（瀏覽器的加密 API 限制）。GitHub Pages 是 https，沒問題；但直接用 `file://` 開啟本機檔案時，雲端功能會顯示為停用。
- 首次輸入密碼要跑 31 萬次雜湊運算，手機上可能要等 0.5～1 秒，之後同一分頁內會快取。
- 因為是一次同步整個空間，旅程很多時每次上傳的資料量會變大。工具已做了兩項優化：天氣預報不同步（各裝置自己抓），以及內容沒變就不重傳。

### 免費額度

Supabase 免費方案有 500MB 資料庫，一個共用空間（含數十趟旅程）大約 1MB 以內。
但要注意：**免費專案若連續 7 天沒有任何活動會被自動暫停**（可在後台一鍵恢復）。旅程規劃期間天天在用不會有事，但放著半年沒碰，回來時可能要先去後台按一下 Restore。

### 誰能看到什麼

拿到空間名稱與密碼的人，看得到**這個空間裡的所有旅程**，也能編輯。
如果有不想給同行者看的旅程，就先不要建立共用空間，或另外開一個空間放。

## 自訂

想改工具名稱、預設清單或配色，全部都在 `index.html` 裡：

| 想改什麼 | 找什麼關鍵字 |
|---|---|
| 網站標題 | `<title>` 與 `brandTitle` |
| 配色 | 檔案開頭的 `:root{ --accent: ... }` |
| 預設藥品 | `function defaultMeds` |
| 預設行李清單 | `function defaultLuggage` |
| 預設行前待辦 | `function defaultPrep` |
| 預設緊急資訊卡 | `function defaultEmergency` |
| 支出分類 | 開頭的 `const CATS` |
| 遊記字數上限 | `const JMAX = 1500` |
